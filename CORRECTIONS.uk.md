## Деталі по кожному виправленню

### REA-001 — Закріпити версії залежностей

**Проблема:** `sushi-config.yaml` оголошує залежності з версією `current`, підштовхуючи збирання до неконтрольованих змін зверху.

**Довід:**
```yaml
dependencies:
  hl7.fhir.uv.ips: current
  hl7.fhir.us.mcode: current
  ncez.cz.fhir.core: current
  ncez.cz.fhir.lab: current
```

**Причина:** версії не закріплені в конфігурації SUSHI.

**Пропонована виправка:** замінити `current` на конкретні стабільні версії (наприклад, `1.1.0`) після перевірки доступних версій у репозиторіях зверху. Зберегти коментар, що ҆уґатвує вибір.

**Файли:** `sushi-config.yaml`

**Тест валідації:** валідувати YAML парсером (наприклад, Python `yaml.safe_load`) та підтвердити, що значення `current` більше не присутнє у залежностях.

**Ризик:** низький.

**Польза:** відтворювані та передбачувані збирання.

**Пріоритет:** негайно.

**Довід:** клон репозиторію не містить директорії `.github` ani файлів тестів.

**Причина:** у IG немає конвеєра неперервної інтеграції.

**Пропонована виправка:** додати робочий процес GitHub Actions, що встановлює SUSHI та валідує генерацію IG із FSH.

**Файли:** `.github/workflows/ci.yml` (новий).

**Тест валідації:** запустити робочий процес на форку/гілці та підтвердити успішне завершення.

**Ризик:** середній (потребує SUSHI на ran-ері CI).

**Польза:** раннє виявлення регресій у профілях FSH.

**Пріоритет:** середній.

### REA-003 — Видалити або заповнити порожній `package-lock.json`

**Проблема:** `package-lock.json` містить лише `"name": "cz-patsum"` та `"packages": {}`, без функції.

**Довід:** вміст файлу (лише заголовок, без пакетів).

**Причина:** lockfile згенеровано без `package.json` ani встановлених залежностей.

**Пропонована виправка:** видалити порожній файл або додати `package.json` з залежностями збирання, якщо такий намір.

**Файли:** `package-lock.json` (видалення) та, опціонально, `package.json` (новий).

**Тест валідації:** підтвердити, що збирання/лінт не залежить від порожнього `package-lock.json`.

**Ризик:** низький.

**Польза:** чистий репозиторій, без плутанини для учасників.

**Пріоритет:** негайно.

### REA-004 — Переглянути розрізнення `open` → `closed` у критичних розділах

**Проблема:** правила розрізнення розділів визначені як `#open` дозволяють непотрібні ресурси.

**Довід:** `CzComposition.fsh:57` (`section ^slicing.rules = #open`) та `knownIssues.md` пункт 3.

**Причина:** рішення проектування ради гнуckoсті за рахунок автоматичної валідації.

**Пропонована виправка:** оцінити критичні розділи (медикаменти, алергії, проблеми) та змінити розрізнення на `#closed` там, де це вимагає безпека клінічна, задокументувавши компроміс.

**Файли:** `input/fsh/profiles/CzComposition.fsh`

**Тест валідації:** згенерувати IG за допомогою SUSHI та валідувати приклади екземплярів проти профілів.

**Ризик:** середній (змінює поведінку валідації клінічних профілів).

**Польза:** суворіша та безpieчна валідація екземплярів.

**Пріоритет:** середній.
